# `checks.md` — Verification Evidence

> Executed against the current source tree (`100%` Go standard library, `0` external dependencies). All metrics come from observed command execution.
>
> `go test ./...` runs hermetically offline using mock `security`/`secret-tool`/`op`/`stty`/`osascript`/`bw`/`psql`/`git`/`claude`/`open` scripts, `httptest` servers (cloud APIs, the Telegram Bot API, the Slack Web API, and the Vercel API), in-process Telegram and Slack stand-ins for the `mintrun init` tests, and temporary `MINTRUN_HOME` and `HOME` directories. It never calls live cloud APIs, Telegram, or Slack, mutates `~/.mintrun`, touches the real macOS Keychain or an IDE's config, or connects to a database. The real macOS Keychain round-trip test is gated behind `-tags integration`.

## 3. Known Limitations & Open Items

| Item | Status | Notes |
| :--- | :---: | :--- |
| Live AWS STS and Google OAuth2 API calls | `unresolved` | Intentionally mocked via `httptest` and pinned to published test vectors; never called with live credentials in automated tests |
| Live `secret-tool` execution on a Linux host | `unresolved` | Verified via mock scripts on macOS; the Linux branch of `NewKeychainVault` requires a Linux host with `libsecret` |
| Real-terminal echo test | `unresolved` | `TestCLISecretPromptHidesEcho` covers `setEcho` (100%) with a stub `stty` and `/dev/null` as `stdin`; no test drives a real terminal, since the Go standard library has no PTY |
| macOS Keychain 24,000-byte secret ceiling | `by design` | A secret too long for one `security -i` line is split into at most 16 parts of 1,500 bytes; a longer one falls back to the encrypted file vault with a warning and requires `MINTRUN_VAULT_KEY` |
| Same-user child process access | `by design` | Documented in [README.md](README.md): `mintrun` keeps raw secrets out of agent context and transcripts, but does not OS-sandbox same-user child processes |
| Child sandbox (`sandbox: true`) | `deferred` | Designed in [plan.md](plan.md) §3 item 1, awaiting approval. A macOS 27.0 spike on a throwaway `HOME`: a `sandbox-exec` profile blocked reading, listing, and writing `~/.mintrun` and stopped `security` from starting a Keychain search, while TLS, `git`, `python3`, and local HTTP still worked; whether a real Keychain item is refused inside is `unresolved`. `no_network` stays open |
| Team relay (`mintrun relay`) | `deferred` | Designed in [plan.md](plan.md) §3 item 6, awaiting approval |
| Parent environment on macOS | `pass` | On macOS 27.0, `ps -E -ww -p $PPID` and `sysctl KERN_PROCARGS2` returned the parent's arguments but not its environment (319 to 742 bytes, canary absent), while the same reads of the child's own pid returned 5,012 bytes with the canary (positive control). Older macOS releases and Linux `/proc/$PPID/environ` are untested here |
| `params` from the CLI | `by design` | Only MCP agents send `params`, so a provider with `allowed_installations` (or a GitHub credential that pins no installation) works over MCP only |
| Live 1Password CLI (`op`) | `unresolved` | `OnePasswordVault` is tested against a mock `op` only: the `stdin` item template, the archiving of older items, and the scrubbed errors have not been run against a real 1Password account |
| Approval on Linux | `by design` | The approval dialog is macOS-only: on Linux `-approve` / `require_approval` asks through Telegram and Slack when `approval-telegram` or `approval-slack` is set and fails closed otherwise |
| Telegram and Slack timeout with the macOS dialog | `by design` | Telegram and Slack stop waiting after 10 minutes, but the macOS dialog has no timeout: when it is one of the channels, it keeps waiting for a click |
| Look-alike characters in approval text | `unresolved` | `strconv.Quote` escapes control, format, and bidi characters but keeps printable non-ASCII as is, so a letter from another script that looks Latin, or stacked combining marks, still shows in the dialog and the Telegram and Slack messages as written; `strconv.QuoteToASCII` would escape them, at the cost of showing every non-ASCII argument as escapes |
| Return on a real approval dialog | `unresolved` | The script sets `default button "Deny"` and `cancel button "Deny"`, `osacompile` of it exits 0, and `TestOSApproval` pins it against a stub `osascript`; no test has pressed Return on a real dialog. To check by hand: run `osascript -e 'display dialog "test" buttons {"Deny", "Allow"} default button "Deny" cancel button "Deny"'` and press Return, which should end it with `User canceled. (-128)` on `stderr` |
| Live Telegram Bot API | `unresolved` | `TelegramApproval` and `TelegramLink` (the link `mintrun init telegram` shows) are tested against an `httptest` Bot API and an in-process stand-in only; neither has run against a real bot |
| Live Slack Web API | `unresolved` | `SlackApproval` and `mintrun init slack` are tested against an `httptest` Web API and an in-process stand-in only; neither they nor the README's app setup have run against a real workspace |
| Real IDEs for `mintrun init mcp` | `unresolved` | `claude mcp add -s user`, Cursor's install link, and the Claude Desktop and Antigravity config paths are checked against stubs, a fake `HOME`, and the vendors' documentation only; `init mcp` has not run against a real Claude Code, Cursor, Claude Desktop, or Antigravity install. Cursor's link is opened on macOS only (elsewhere it is printed), and `CLAUDE_CONFIG_DIR` is not read: `doctor` looks for Claude Code's entry in `~/.claude.json` only |
| Live Bitwarden and Vercel | `unresolved` | The `bitwarden` and `vercel` example plugins are tested against a stub `bw` and an `httptest` Vercel API only |
| Audit read time | `by design` | `TailAudit` bounds memory by `limit`, but every read still scans the whole of `~/.mintrun/audit.jsonl`; seek back from the end if the log reaches gigabytes |
| File-vault copy left without a passphrase | `by design` | Without `MINTRUN_VAULT_KEY`, a keystore store cannot decrypt an existing `vault.json`, so it only warns that an older copy of the key may remain; once the passphrase is set, a failed keystore lookup can return that copy. Running `secret set` again with the passphrase set removes it |
